## Механизм тегирования данных

Предлагаю внедрить **метаданные-теги** на уровне приложения и БД:

```yaml
# Пример структуры тега для медицинской записи
data_tag:
  classification: "special_personal_data"  # категория по 152-ФЗ
  sensitivity: "high"                      # уровень чувствительности
  owner_role: "doctor"                     # роль-владелец данных
  access_policy: "rbac:medical_staff"      # политика доступа
  retention_days: 25550                    # 70 лет — срок хранения медкарт
  encryption_required: true                # флаг шифрования
  audit_level: "full"                      # уровень логирования
  pii_fields: ["diagnosis", "test_results", "prescriptions"]  # поля с ПДн
```

 **Инструменты реализации** **:**

* **Apache Atlas** или **DataHub** — для каталога данных и тегирования elma365.com
* **PostgreSQL Row-Level Security + Labels** — для политик на уровне БД
* **OPA (Open Policy Agent)** — для централизованного управления политиками доступа
* **HashiCorp Vault** — для управления ключами шифрования и секретов

## Меры обеспечения конфиденциальности в потоках данных

 Контрольные точки безопасности :

1. Входная точка : Обязательная аутентификация сотрудника (MFA), валидация сессии
2. API Gateway :

   - Валидация входных данных (schema validation)
   - Логирование всех запросов с маскированием ПДн
   - Rate limiting для предотвращения brute-force
3. Уровень БД :

   - Row-Level Security для изоляции данных пациентов
   - Transparent Data Encryption для шифрования «на отдыхе»
   - Автоматическое тегирование полей с ПДн при вставке
4. Уровень хранения ключей : Выделенный Vault-кластер с аудитом доступа к секретам
